# recon-604 plan: Push to VECO (test database)
**Goal:** a second option on the Vico page that previews (read-only), pushes all-or-nothing (Transaction 79 cols + Allocation 14 cols), cross-checks, lists and deletes its own rows in `Test Database Read Write`. Spec: plans/recon-604-veco-direct-push.md. All tests use fakes; nothing calls a real VECO.
**Scope note:** the contract's Exclusions list repeats in-scope paths (app.ts, web/src/features/vico/**, server/test/**, .env.example, jobs/veco-sync/**). Scope wins. If `hx drift` flags them, the coordinator raises it with the user. Do not widen scope.

## Decisions (final)
D1 Source bank = `bank_accounts.code` via receipts.bank_transaction_id→bank_transactions.bank_account_id. NULL→`MANUAL` (label "Manual / no bank line"). Per-bank totals key on this code.
D2 Every VECO lookup (Staff, Tenant…) is a read-only SELECT over the RW connection against the test DB (live and test ids differ). The read-only VECO_MCP_URL is never used. Each operation first runs `SELECT DB_NAME() AS db`. Anything other than the target refuses with 409 `wrong_database`.
D3 First-ever department: the UI sends `departments: {[receiptId]: 'Owner'|'Tenancy'}` in both the preview and push bodies. A pick only applies when VECO has no previous department. Without a pick the receipt is held with `department_not_chosen`.
D4 Idempotency: the browser makes `crypto.randomUUID()` when the confirm modal opens and keeps it for retries. It is stored in `veco_push_batch.idempotency_key UNIQUE`. A replay by the same user returns the stored batch with 200 `{replay:true}` and makes no VECO call. The same key from another user gives 409.
D5 "Sent" marker = an `external_refs` row (system 'vico', entity 'receipt', entity_id receipt, external_id `veco-push:<TransactionPK>`, external_key2 NULL). v_vico_export then excludes the receipt, so the manual export can't send it, and listExports/getExportFile (which filter external_key2 NOT NULL) stay unchanged. Delete or failure removes these rows.
D6 Preview writes nothing anywhere. The `previewed` status stays in the CHECK (spec §6) but is never written. Push statuses: pushing→pushed|verified|failed→deleted.
D7 Constants live in code (settings.ts), with no DB override: TARGET_DB, COMPANY_FK `46F81970-9647-46A5-B5B3-352150533B39`, BANK_FK `877A0B7D-802E-4C49-88C7-A74337DCD08F`, BANK_SORT `20-79-06`, BANK_ACCOUNT `43789276`, MAX_PUSH_RECEIPTS 500.
D8 Push permission = role admin|accounts AND `veco_staff_link.can_push`. Auto-link by email (exactly 1 Staff row) inserts can_push=false. An admin grants can_push (the three named importers) and can set or override StaffPK. Admin links are never overwritten.
D9 dtePosting = push start in UK time with ms floored to a multiple of 10, so datetime stores it exactly. dteStatus = the same value. All rows in a push share it.
D10 A second push in the same UK minute (same batch ref, status pushing|pushed|verified) gets 409 "wait until the next minute".
D11 Cross-check display: date, TID, department, amount and banking ref come from the VECO read-back. Tenant name comes from VECO `Contacts.strAddressTitle`. Property and landlord come from Omnia Recon (receipt→tenancy→property/landlord), because VECO's columns for those are unverified.

Why: spec §6. The partial index allows a re-push after a delete.
2. **mcp-client.ts:** extract `openSession()`. Add `export interface SqlBatchRunner { executeBatch(batchSql: string): Promise<string> }` and `export function createMcpSqlClient(o: McpSqlSourceOptions & { clientName?: string }): SqlSource & SqlBatchRunner`. executeBatch sends `batchSql.trim()` unwrapped and returns `toolText(result)`, which throws VecoSourceError on isError. `createMcpSqlSource` becomes `{ queryRows }` of the client with clientName 'omnia-recon-veco-sync' and identical behaviour. 3. **settings.ts:** the D7 constants plus `Department = 'Owner'|'Tenancy'`. **config.ts:** `loadVecoPushConfig(env=process.env): { rwMcpUrl: string|null }`, a zod `z.url()` on VECO_RW_MCP_URL where empty means null. On an invalid value, throw `Invalid VECO push configuration: VECO_RW_MCP_URL <issue>` and never echo the value.
4. **uk-time.ts:** `ukParts(at: Date): {y,mo,d,h,mi,s,ms}` uses Intl `en-GB` with timeZone 'Europe/London', hourCycle 'h23' and formatToParts, plus ms = `Math.floor(at.getUTCMilliseconds()/10)*10`. Also `ukDateTimeLiteral(p)` → `YYYY-MM-DDTHH:MM:SS.mmm`, `batchReference(p)` → `YYYY-MM-DD-HH-MM`, `bankingRef(p,i)` → `S${YYYYMMDD}-${pad4(i)}`, and `vecoReference(p, rnd)` → `${L(h)}${ss}${rnd.digits2()}${L(mo)}${mi}${dd}-${rnd.hex8()}`, where `L(n)=String.fromCharCode(65+n)`, `[mm]` is MINUTES and dd is the day. Example: 14 Oct 14:17:06 → `O06xxK1714-XXXXXXXX`.
5. **sql-literal.ts:** `nstr(v)` → NULL or `N'…'` with `'` doubled; it rejects `\u0000`. `guid(v)` matches /^[0-9A-F]{8}(-[0-9A-F]{4}){3}-[0-9A-F]{12}$/i → `'UPPER'`. `dt(v)` matches /^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\d\.\d{3}$/ → `'v'`. `num(v)` matches /^-?\d+(\.\d+)?$/ → bare. `bit(0|1)`. `guidList(pks)` / `nstrList(vs)` → comma-joined. Each throws `Error('unsafe SQL value')` on a bad value. `formatValue(kind, v)` dispatches on kind and returns NULL for null.
6. **columns.ts:** `TRANSACTION_COLUMNS` holds the 79 names in spec §2a order, with `TRANSACTION_KINDS` for the 30 filled ones (guid: TransactionPK, CompanyFK, OfficeFK, StaffFK, OwnerGroupFK, PropertyFK, TenancyFK, ContactFK, StatusStaffFK, BankFK; str: strType, strAccountPeriod, strBankingRef, memDescription, strDepartment, strStatus, strReference, strTransactionStatus, strBatchReference, strStandingOrderReference; dt: dtePosting, dteDate, dteStatus; num: dblAmount, dblVAT, dblGross, dblTaxRate, lngDaysDelay; bit: blnDeleted, blnOwnerPayment). `TRANSACTION_NULL_COLUMNS` = the remaining 49. `ALLOCATION_COLUMNS` holds 14 (§2b order as listed), with 7 kinds.
7. **classify.ts:** `classify(cands: Candidate[], lookups: TenantLookupRow[], o: {bankOk: boolean; sentIds: Set<string>; departments: Record<string,Department>}): {ready: ReadyInput[]; held: Held[]}`. Checks run in this order, first hit wins: already_sent, amount_not_positive, bank_account_mismatch, tid_invalid (/^[A-Za-z0-9]{1,20}$/), tid_not_found, tid_duplicate (2+ rows), tenancy_missing (propertyFk null), owner_none/owner_multiple, office_none/office_multiple, contact_name_missing (no lastDescription and empty addressTitle), department_not_chosen. `HELD_MESSAGES` record gives each code its English text.
8. **row-builder.ts:** `buildRows(ready: ReadyInput[], ctx: {at: Date; staffFk: string; uuid?: () => string; rnd?: RandomSource}): {batchReference; rows: BuiltRow[]}`. It sorts by paymentDate, tid, receiptId and numbers banking refs 0001…n. It fills all 79 keys (49 null) per §2a: memDescription = lastDescription verbatim ?? `'Rent Received  From ' + addressTitle`, strDepartment = lastDepartment ?? pick, lngDaysDelay = delayPayment ? 7 : 0, strAccountPeriod from paymentDate, and the 7 allocation values per §2b. strReference regenerates on a duplicate inside the push. Defaults: `randomUUID().toUpperCase()` and crypto randomInt/randomBytes.
9. **sql-batches.ts** (pure string builders, every text starts with a tag comment such as `/* omnia:lookup */`). Shapes:
   - lookup (≤500 TIDs per query): `SELECT tn.strStandingOrderReference AS tid, tn.TenancyFK AS tenancyFk, tn.ContactFK AS contactFk, ty.PropertyFK AS propertyFk, ty.strTenancyOfficeName AS officeName, (SELECT COUNT(*) FROM dbo.Owns o WHERE o.PropertyFK=ty.PropertyFK AND o.blnCurrentOwner=1) AS ownerCount, (SELECT TOP 1 o.OwnerFK …same WHERE) AS ownerFk, (SELECT COUNT(*) FROM dbo.Office f WHERE f.strOfficeName=ty.strTenancyOfficeName) AS officeCount, (SELECT TOP 1 f.OfficePK …) AS officeFk, p.blnDelayPayment AS delayPayment, CAST(c.strAddressTitle AS nvarchar(max)) AS addressTitle, (SELECT TOP 1 CAST(t.memDescription AS nvarchar(max)) FROM dbo.[Transaction] t WHERE t.strType='SLP' AND t.strBatchReference IS NOT NULL AND t.memDescription LIKE N'Rent Received  From %' AND t.ContactFK=tn.ContactFK ORDER BY t.dtePosting DESC) AS lastDescription, (SELECT TOP 1 t.strDepartment … AND t.TenancyFK=tn.TenancyFK ORDER BY t.dtePosting DESC) AS lastDepartment FROM dbo.Tenant tn LEFT JOIN dbo.Tenancy ty ON ty.TenancyPK=tn.TenancyFK LEFT JOIN dbo.Property p ON p.PropertyPK=ty.PropertyFK LEFT JOIN dbo.Contacts c ON c.ContactPK=tn.ContactFK WHERE tn.strStandingOrderReference IN (N'…',…)`
   - staff: `SELECT StaffPK AS staffPk FROM dbo.Staff WHERE strEmailAddress1 = N'…'`, and `SELECT COUNT(*) AS n FROM dbo.Staff WHERE StaffPK='…'`.
   - insert batch (`insertBatchSql(rows)`), in this order: `SET XACT_ABORT ON; SET NOCOUNT ON;` → `IF DB_NAME() <> N'Test Database Read Write' THROW 50001, N'Omnia Recon refuses to write outside Test Database Read Write', 1;` → `BEGIN TRY BEGIN TRAN;` → three `IF EXISTS(...) THROW` checks, one each on TransactionPK IN, AllocationPK IN and strReference IN (50002–50004) → `INSERT INTO dbo.[Transaction] (<79 cols>) VALUES (…),(…)` in chunks of ≤500 tuples → `INSERT INTO dbo.Allocation (<14 cols>) VALUES …` → `IF (SELECT COUNT(*) …TransactionPK IN…) <> n THROW 50005 …;` → `COMMIT TRAN; END TRY BEGIN CATCH IF @@TRANCOUNT > 0 ROLLBACK TRAN; THROW; END CATCH;` → `SELECT N'OMNIA_PUSH_OK' AS outcome;`
   - read-back (via queryRows): the 30 filled Transaction cols (memDescription CAST nvarchar(max)) plus `a.AllocationPK AS a_AllocationPK, a.DebitTransactionFK AS a_DebitTransactionFK, …` (7, `a_` prefix), plus `CAST(c.strAddressTitle AS nvarchar(max)) AS tenantName`, `FROM dbo.[Transaction] t LEFT JOIN dbo.Allocation a ON a.DebitTransactionFK=t.TransactionPK AND a.AllocationPK IN (…) LEFT JOIN dbo.Contacts c ON c.ContactPK=t.ContactFK WHERE t.TransactionPK IN (…)`.
   - delete batch: the same guard, XACT_ABORT and TRY/TRAN. Then `IF EXISTS(SELECT 1 FROM dbo.Allocation WHERE (DebitTransactionFK IN (tx) OR CreditTransactionFK IN (tx)) AND AllocationPK NOT IN (al)) THROW 50006, N'Other VECO rows now reference these receipts; delete refused', 1;` → `DELETE FROM dbo.Allocation WHERE AllocationPK IN (al);` → `DELETE FROM dbo.[Transaction] WHERE TransactionPK IN (tx);` → COMMIT/CATCH.
   - remaining: `SELECT (SELECT COUNT(*) …[Transaction] WHERE TransactionPK IN…) AS transactions, (SELECT COUNT(*) FROM dbo.Allocation WHERE AllocationPK IN…) AS allocations, (SELECT CAST(ISNULL(SUM(dblAmount),0) AS decimal(18,2)) …) AS total`.
10. **gateway.ts:** `interface VecoGateway { assertTargetDb(); findStaffByEmail(email): Promise<string[]>; staffExists(pk); lookupTenants(tids): Promise<TenantLookupRow[]>; insertReceipts(rows: BuiltRow[]); readBack(tx, al): Promise<Record<string,unknown>[]>; deleteReceipts(tx, al); countRemaining(tx, al): Promise<{transactions; allocations; total: string}> }`. `createSqlGateway(sql: SqlSource & SqlBatchRunner, targetDb = TARGET_DB)` throws if targetDb ≠ TARGET_DB and parses rows with type checks. **memory-gateway.ts:** `createMemoryGateway(seed: {dbName?; staff: {staffPk; email}[]; lookups: TenantLookupRow[]})` returns a gateway plus `{transactions: Map; allocations: Map; calls: string[]; failNextInsert?: Error}`. It is all-or-nothing, throws if a PK exists, and is used only by tests (never wired in main()).
11. **crosscheck.ts:** `crossCheck(items: StoredItem[], readBack): VerifyResult {ok; checkedAt; rows: {receiptId, transactionPk, tid, date, tenantName, property, landlord, department, amount, bankingRef, ok, diffs: string[]}[]; before/after: {count; total; byBank: {bank,count,total}[]}}`. Values are normalised by kind before comparing: guid uppercase, num `toFixed(2)`, bit 0/1 (true→1), dt padded to `.mmm`, str exact. Diff names are `dblAmount` or `Allocation.dblPercentage`. A missing row gives the diff `row missing`.
12. **veco-push.service.ts** (`deps = {pool, gateway: VecoGateway|null, now: () => Date}`). Every gateway call goes through `notConfigured()` (409 `veco_push_not_configured` when gateway is null), and VecoSourceError maps to 409 `veco_error` with the message truncated to 300 chars. Functions:
   - `getStatus(deps, db, user)`: auto-links per D8 and returns `{configured, targetDb, me: {linked, staffFk, canPush, source, linkProblem}}`.
   - `previewPush(deps, user, {receiptIds, departments})`: candidates come from v_vico_export JOIN receipts/tenancies/properties/landlords/bank lines/lead tenant (the vico service's PENDING_SELECT shape, plus D1 and the property/landlord fields). Ids that are not pending count as already_sent. It then runs assertTargetDb, lookupTenants and classify, and returns `{ready, held, byBank, total, readyTotal}`.
   - `pushToVeco(deps, db, user, {idempotencyKey, receiptIds, departments})`: (a) replay check. (b) Requires a link with can_push, else 403 "No VECO user linked" or "no VECO push permission". (c) Runs the preview logic and buildRows(at=now()); 409 if nothing is ready. (d) In `db.tx`: `pg_advisory_xact_lock(0x7631c0)` (the same lock as the Vico export), re-select pending (now-missing ids are moved to held already_sent), the D10 guard, insert the batch (`pushing`) and items, insert the external_refs (D5). (e) `gateway.insertReceipts`. (f) Read back. All n rows present means pushed. Zero rows after an error means failed: delete the refs and store the error. A partial count means failed with `partial — check VECO` and the refs are kept. (g) crossCheck, then status verified, or pushed if not ok. Returns `{batch, verify, held, replay:false}`.
   - `verifyBatch` re-reads; a `pushing` batch is reconciled the same way as (f). `readbackCsv` runs verifyBatch, then builds a CSV with a formula-safe cell() and columns Date, TID, Tenant, Property, Landlord, Department, Amount, Banking ref, TransactionPK, Check, Differences. `deleteBatch` checks status pushed|verified, target_db, can_push and assertTargetDb, runs deleteReceipts and countRemaining (must be 0/0/0.00, else 409 and nothing changes), then a tx sets batch and items deleted and removes the refs. `listBatches` (100 newest, joined app_users.full_name), `listStaffLinks` and `saveStaffLink` complete the set.

## Edge cases
- A pending set over 500 → the first 500 by date.
- A receipt exported manually between preview and push → held already_sent.
- A crash mid-push leaves the batch `pushing`; View reconciles it.
- Other VECO allocations referencing our rows → delete refused.
- An empty addressTitle → held.
- The vico settings bank ≠ 20-79-06/43789276 → everything held.

## Risks / rollback
- VECO PK column names TenancyPK/PropertyPK/ContactPK are assumed (Office/Staff are confirmed by the spec). A wrong name only fails the read-only preview, and the user's first preview will show it.
- Whether MCP execute_sql accepts multi-statement batches is unproven. Success is judged by the read-back, never by the marker.
- Rollback: revert the commit, then `DROP TABLE veco_push_item, veco_push_batch, veco_staff_link`. VECO is untouched until a user clicks Push.

- Changes to the vico service and routes.
